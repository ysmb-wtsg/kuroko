# ADR 0012: セッション一覧サイドバー（Claude Code 専用）

## ステータス

採用（2026-11-03）

## コンテキスト

メインタブは横並びのタブバーでしか見えず、過去の Claude Code セッションへ戻るには
ターミナルで `claude --resume` を打つ必要があった。Claude デスクトップアプリのように、
セッションを縦に並べて選ぶだけで切り替え・再開できるようにしたい。

セッション履歴の形式はエージェントごとに異なるため、プロバイダー抽象（`AgentProvider`）の
上で汎用化するとコストが大きい。kuroko の主対象は Claude Code であり、
セッション機能は Claude Code に限定してよいとユーザーが判断した。

検討した代替案:

- **右サイドパネル（`SideContent`）の3つ目として載せる**: スロット追加が不要で安いが、
  ファイルツリー・Git と排他になり、ファイルを見ながらセッションを切り替えられない
- **横タブバーを廃止して縦タブに置き換える**: ボトムターミナルのタブと操作体系が分かれ、
  既存の `n` / `x` / `]` / `[` 操作も作り直しになる。今回は見送る

## 決定

1. **左側に固定スロットとしてセッション一覧サイドバーを追加する**（ADR 0001 の固定スロット方式に
   従う）。グローバルモードの `s`（`Action::ToggleSessions`）で表示を切り替える。
   表示状態と幅比率は `session.json` に保存する
2. **上段に開いているメインタブ、下段に過去セッションを並べる**。Enter で、タブなら
   そのタブへ切り替え（`Action::SelectTab`）、過去セッションなら `claude --resume <id>` を
   新しいタブで起動する（`Action::ResumeSession`）。タブで開いているセッションは過去セッション
   側に重複表示しない
3. **kuroko が起動する Claude Code には `--session-id <uuid>` を付け、セッションIDを
   kuroko 側で採番する**。これによりタブとセッションの対応が分かり、同じセッションを
   二重に開かず既存タブへ切り替えられる
4. **履歴は `~/.claude/projects/<cwd を英数字以外 `-` に置換>/*.jsonl` から読む**
   （`$CLAUDE_CONFIG_DIR` があればそちらを使う）。タイトルは
   `custom-title` → `ai-title` → `last-prompt` → 最初のユーザー発言 の順に採用し、
   どれも無いセッションは表示しない
5. **履歴の読み込みは別スレッドで行い、表示中のみ5秒ごとに再読み込みする**。
   jsonl は数MBになり得るため、mtime とサイズが変わったファイルだけ再解析するキャッシュを持つ
6. セッション機能は Claude Code のみ対応とする。`BuiltinProvider::supports_sessions()` が
   false のプロバイダー（Codex 等）ではセッションIDを付けず、そのタブは履歴と対応付けない。
   過去セッションの再開はメインのプロバイダー設定に関わらず Claude Code で行う

## 結果

- タブとセッション履歴を1か所で見渡せ、選ぶだけで切り替え・再開できる
- jsonl の形式は Claude Code の内部仕様であり、将来の変更でタイトル抽出が壊れる可能性がある。
  その場合も最初のユーザー発言へのフォールバックで一覧自体は表示を保つ
- Claude Code 内で `/clear` すると新しいセッションIDに切り替わるため、そのタブは
  旧IDのまま扱われ、新しいセッションは履歴側に表示される
- Codex / カスタムプロバイダーのコード自体は今回削除していない
