# ADR 0011: エディタのフォールバックで nvim を優先する

## ステータス

採用（2026-11-03）。ADR 0008 の決定4（エディタの解決順）を置き換える

## コンテキスト

ADR 0008 では、エディタを 設定 `krk.opt.editor` → `$EDITOR` → `vim` の順で解決していた。
`$EDITOR` を設定していない環境では `/usr/bin/vim` が起動する。macOS 標準の vim は
vimrc が無いとシンタックスハイライトも無効なため、ファイルツリーから `e` で開くと
素の vim になり、編集体験が悪かった。一方、利用者の多くは設定済みの nvim を持っている。

## 決定

エディタの解決順を次のとおりにする。

1. 設定 `krk.opt.editor`
2. 環境変数 `$VISUAL`
3. 環境変数 `$EDITOR`
4. `nvim`（PATH上にある場合）
5. `vim`

`$VISUAL` は全画面エディタを指定する慣習的な変数で、ダイアログ内で全画面のエディタを
起動する kuroko の用途に合うため、`$EDITOR` より優先する。

## 結果

- 設定も環境変数も無い環境でも、nvim が入っていればユーザーの設定（プラグイン・ハイライト）
  がそのまま使われる
- `$VISUAL` と `$EDITOR` を別々に設定しているユーザーは、kuroko で開くエディタが
  `$VISUAL` 側に変わる
